# Current verification baseline

From a fresh shell at the repository root, run:

```sh
/opt/homebrew/bin/node tools/verify-current.mjs
```

This is the single cumulative baseline for the current Darwin/arm64 reference tree. It exits nonzero on the first failed current step and prints `RESULT PASS` only after all current steps pass. In an evidence-producing unit, wrap that exact command with `didrun run --`, claim the successful event immediately, and commit. In this managed environment, seal only with Git-note write authority, confirm `git notes --ref=didrun show HEAD` succeeds, and then require `NO_COLOR=1 didrun verify --strict` to exit `0`. A direct run is useful local evidence, but it has no didrun grade.

## Mixed didrun object namespace for C1 local evidence

The C1B development gate exposed a checker defect before freeze: the pinned ignored C1 ledger stores two intentional object namespaces under `.didrun/objects/`. Flat `objects/<64-lowercase-hex>` files are didrun stdout/stderr/transcript capture blobs named by SHA-256 of their raw bytes. The existing objects-only SHA-256 manifest continues to bind the stored path, size, and raw bytes of both namespaces together.

Local evidence validation is reject-by-default and resource-bounded before content reads. Flat names must match raw SHA-256. Fan-out files must consume one complete zlib stream of at most 4 MiB inflated bytes without trailing input, expose a canonical Git object header and exact declared payload size, and match the SHA-1 object identity encoded by their path. Every other namespace, malformed stream, over-limit inflation, header/size mismatch, identifier mismatch, observed symlink, or nonregular entry also fails. Session stdout/stderr/transcript references must be valid flat identifiers, and their set must equal the flat capture-blob inventory. SHA-1 here is the repository's Git object-format identity; archive integrity remains the declared SHA-256 manifests. ## Output contract

The stable output classes are:

```text
COUNTERSHAPE_VERIFY_V1 ... general_jobs=2 nested_jobs=1 gomaxprocs=2 ...
AUTHORITY ...
ROSTER CURRENT ...
HISTORICAL-ONLY NOT-RUN ...
CURRENT [NN/NN] START ...
CHILD ...
CURRENT [NN/NN] PASS ...
RESULT PASS current=N/N historical_not_run=M
```

On failure, the failing row is `CURRENT ... FAIL`, no later current row is spawned, and the summary is `RESULT FAIL`. The terminal `RESULT PASS` is printed only after the current resource-finalization row has removed the private run root and released the verifier lock; cleanup or release failure therefore cannot leave an overall PASS marker. `HISTORICAL-ONLY NOT-RUN` means exactly that; it is not a current-tree compatibility claim.
