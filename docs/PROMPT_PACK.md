## How to run this pack

Execute one prompt at a time, in order, in a fresh chat with the repository root as the working directory. A prompt is independently resumable but not independent of prior artifacts: it must read the brief, `docs/SEMANTICS.md`, `docs/PROJECTION_ALGEBRA.md`, latest handoff, owning research, current source, and prior sealed receipt. Those two semantic documents are mandatory reads for every downstream unit even if an older prompt's inline read list omits them. Do not paste all prompts into one context. Do not begin the next prompt until the current prompt's latest commit is sealed and `NO_COLOR=1 didrun verify --strict` exits 0.

The living authority order is:

1. `docs/CONCEPT_BRIEF.md` for the locked product and truth contract;
2. `research/deep-dive/11-p07-implementation-red-team.md`, then `08-RED_TEAM.md` and `07-SYNTHESIS.md`, for implementation-time corrections, cuts, and blocker reasoning;
3. the current prompt for unit ownership and acceptance;
4. `docs/HANDOFF_MODE_C.md` for observed repository state.

An implementation-time red-team correction section inside a prompt supersedes conflicting older prompt prose when that correction narrows authority, is covered by the planning validator, and is committed and receipted with the owning unit. Broadening authority or changing acceptance scope requires a separately receipted planning-contract change.

If these conflict, preserve the narrower truth claim and record the discrepancy before editing. Never silently broaden scope.

### Product and novelty boundaries

### didrun discipline—every shippable slice

Every load-bearing verification command runs as `didrun run -- <actual command>`: format, lint, unit/property/state/mutation tests, race tests, builds, fixtures, package smoke, Playwright, axe, Lighthouse, visual capture automation, security matrices, performance studies, external critic, and final audits. Read-only inspection need not become a product claim. An unwrapped check is `UNRECEIPTED`.

At each shippable boundary:

1. run the genuine final verification commands through didrun against the intended tree;
2. immediately after each final successful verification command, declare only the supported truthful claim without explicit event addressing; do not batch claims after later events, because didrun 0.1.0's observed default-event behavior can otherwise bind a claim to the wrong command;
3. stage the exact unit, review the diff and secret/private-artifact exposure, and commit;
4. seal that commit with didrun;
5. loop on `NO_COLOR=1 didrun verify --strict` until exit 0.

A nonzero strict exit means the unit is not done. Read the exact `failed`, `unknown`, `stale`, or coverage reason; repair the real cause; rerun affected verification through didrun; declare new honest claims; create a new commit; reseal; and reverify. Do not weaken or delete a test, claim, threshold, fixture, receipt, or old commit. Failed receipts on old commits are permanent history. `tree-exact` and `scope-exact` describe evidence/tree binding, not independent truth. Any capability without its own receipt is literally `UNRECEIPTED`.

## Whole-system done condition
