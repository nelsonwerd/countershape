### Canonical body versus wire envelope

`artifact_digest` is the external content address of an artifact's canonical semantic body; it is intentionally excluded from the bytes it addresses. Including a digest inside its own hash input would create an unsatisfiable self-reference. The U0 JSON examples and schemas are target storage/wire envelopes: their `artifact_digest` accompanies the canonical body but is not a field of that body's hash preimage. U1's `CanonicalBytes()` methods return the identity-bearing body with `schema_version`, `kind`, and all semantic fields, while `Digest()`/`ArtifactDigest()` returns its separately domain-hashed address. U1 does **not** yet implement a storage codec that projects those runtime bodies into every target schema. Planning-example validation proves only that the checked-in planning examples satisfy the checked-in target schemas; it does not establish runtime/schema round-trip parity. That codec boundary is deferred to U6 and remains `UNRECEIPTED`.

The ruling boundary is intentionally narrow:

- actions and predicate arrays have no defaults;
- a domain supplies a closed typed field registry;
- missing and present-empty values remain different tagged values;
- allow-many is a canonical set of complete tuples, never independent per-field value sets;
- every allowed tuple must differ from every disallowed confirmed outcome on the selected fields;
- empty, invalid-UTF-8, unknown, duplicate, incomplete, or type-invalid fields are refused;
- `REJECT_ALL`, `DEFER`, and `REFINE` construct only a sealed `NoncompilableRuling`;
- `ALLOW_OBSERVED` and separately reviewed `CUSTOM_EXPECTATION` can construct a sealed `CompilableRuling`; and
- no compilation boolean exists for an API or emitter to coerce.

## Contract correction discovered during implementation

Static red-team review found a contradiction in U0: `docs/ARCHITECTURE.md` said `CandidateExecutionKey` included the stimulus, while reduction requires comparing the same labeled candidate map across an original and smaller stimulus. If the stimulus were inside the key, every shrink would replace every key and could never be `PRESERVES`.

U1 corrects the controlling contract: `CandidateExecutionKey` is only the stable wire/display reference and excludes stimulus. The opaque `CandidateExecutionBinding` retains the full executable candidate identity, and allocating structural evidence requires both that binding and the actual matching `WorldPlan`. `StableBatch` and the enclosing `CandidateOutcomeMap` bind stimulus separately.

Reduction never compares a naked digest. It first compares the full typed maps for the same plan, comparison envelope, stimulus-independent comparison basis, expected roster, eligible set, exclusions, and exclusion classifications. Only comparable maps may use equality of the complete sorted candidate-key-to-projection-fingerprint digest to decide `PRESERVES` versus `CHANGES`; every comparability failure is `UNRESOLVED`.

Semantic canonical bodies also exclude their own `artifact_digest`: hashing bytes that contain their resulting hash is circular. `Digest()` is the external content address; U0 JSON examples represent storage/wire envelopes around the hashed semantic body.

### Adversarial rebuild, not a rubber stamp

The first compiling U1 draft was rejected before sealing. Two independent static audit lanes demonstrated executable-plan digest collisions through invalid UTF-8 repair, contradictory control facts that could become eligible, omitted candidates in supposedly complete maps, generic artifact-stage forgery, caller-authored reduction completeness, and `ALLOW_OBSERVED` tuples unbound from confirmation. Those were authority failures, not missing assertions.

The boundary was redesigned around these cuts:

- typed identity is assembled directly from canonical values; `encoding/json` cannot repair identity-bearing strings;
- the expected candidate roster is an input authority and entries plus exclusions must cover it exactly;
- `CandidateOutcomeMap` and its `DivergentBaseline` refinement are distinct;
- the preservation-map digest and evidence-bearing outcome-artifact digest are distinct named types;
- captured behavior and controls are sealed alternatives rather than compatible booleans;
- generic artifact `(stage,digest)` adjacency is not a semantic transition API;
- `ALLOW_OBSERVED` selects from a sealed confirmed-outcome set and derives the complete allowed/disallowed partition; and
- U1 exposes logical reduction evidence only. It cannot construct durable `ONE_MINIMAL_UNDER`; that authority arrives with the U5 store-backed sweep.

A second adversarial pass found no remaining P0/P1 authority defect after the boundary was rebuilt. A later fuzz-specific review then found that cardinality plus non-overlap did not prove exact selected-ID membership; the exhaustive and fuzz properties now require exact set equality and exact complement coverage.

The roster statement is deliberately structural: U1 neither proves that a key belongs to the plan's Git candidate set nor enforces `Budgets.CandidateCount == len(expectedRoster)`. U2 must derive that binding. Likewise, U1 records and checks caller-supplied schedule ordinals but states rotation only as `NOT_ESTABLISHED_IN_U1`; physical scheduling and rotation belong to U3.

## Locked U1 authority chain

The controlling read order is `docs/SEMANTICS.md` followed by `docs/PROJECTION_ALGEBRA.md`. The chain is `WorldPlan + CandidateExecutionBinding + stimulus + attempt identity -> structural WorldInstance -> complete InstanceMeasurements -> AssessComparison`. Assessment persists either a concrete `ComparisonAdmission`, including the exact sorted measurement matrix, or a `RejectedComparison`. Every repetition has its own admission artifact; candidate batches may join one outcome map only when their ordered admission-digest sets match exactly. `ComparisonBasisDigest` deliberately excludes stimulus, purpose, and concrete measurement rows so baseline and neighbor runs can remain comparable.

Rejection is a pre-batch refusal: it yields no token, trial, stable batch, or outcome map. Admission tokens are deterministic, internal, ephemeral row capabilities. `WorldInstance` records declared structural consistency only; roots, ports, PIDs, clocks, platform/tool facts, lifecycle, teardown, and other host observations belong to later measurement or process-receipt artifacts. None of those edge facts is established by U1.
