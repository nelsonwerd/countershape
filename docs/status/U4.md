## Deep-dive correction before implementation

The U4 architecture review did not rubber-stamp the prompt. It found two load-bearing gaps:

1. U0 declared a `ready-byte` signal but never defined its bytes. U4 now locks `ONE_BYTE_0X01_THEN_EOF_V1`: a dedicated inherited pipe must produce exactly byte `0x01`, then EOF, inside `readiness_ms`. Empty EOF, a different byte, extra bytes, missing EOF, timeout, cancellation, or child exit is a control and cannot advance readiness. This pipe is not HTTP and cannot warm application state.
2. U2/U3's physical runner is intentionally one-shot and would time out a healthy service before probing it. U4 therefore adds one private HTTP-specific service sequencer plus one thin opaque-binding `ExecuteHTTP` edge inside `internal/world`, reusing the established allocation and process-group helpers. It is not a neutral service primitive. The CLI path stays unchanged. No exported arbitrary callback runner and no HTTP branch in generic truth is permitted.

## Locked U4 physical profile

- One fresh selected Git candidate is materialized into one new world per trial.
- The parent binds a fresh TCP4 listener on literal `127.0.0.1:0` and passes its descriptor as child fd 3. It passes the readiness writer as child fd 4 and closes its own child-side duplicates immediately after start.
- The curated dependency-free Node fixture attaches to fd 3 and writes the exact readiness byte to fd 4 only from its listening callback, then closes fd 4.
- After exact readiness, the runner performs one raw cleartext HTTP/1.1 exchange to the allocated literal loopback address. It uses no DNS, proxy, redirect, cookie jar, compression, retry, TLS, WebSocket, chunking, streaming, or external host.
- The request encoder preserves method, clean origin path, ordered query entries including key-only versus empty value, ordered duplicate headers, and absent versus present-empty body. Runner-owned `Host`, `Connection: close`, and conditional `Content-Length` cannot be supplied by the stimulus.
- The response parser requires one bounded final HTTP/1.1 response with a canonical decimal `Content-Length`, rejects interim responses, transfer/content encodings, obs-fold, malformed or oversized headers/body, length mismatch, and trailing bytes, and preserves ordered response headers plus exact body bytes. A complete `500` is program behavior; transport or protocol failure is a control.
- Teardown first spends one bounded portion of the declared budget harvesting a cooperative natural child exit, then probes the owned process group and performs TERM/grace/KILL only if present; child wait, stdout/stderr drains, and final observed group absence are still mandatory. A clean cooperative lifecycle records exact pre-TERM `ABSENT` with no signal. A complete response followed by natural nonzero exit, teardown error, or orphan uncertainty remains ineligible.

2. `DialContext` governed connection establishment but not an already-connected read. The exchange now installs the effective parent/probe deadline and advances the socket deadline when the context is cancelled; physical stall tests exercise cancellation and the shorter inherited deadline.
3. Readiness classification depended on Go `select` choice when child exit and exact bytes became ready together. 5. A valid response followed by natural exit `64` could remain eligible. Natural nonzero/signal service termination is now a typed probe-transport control; owner-issued teardown signals remain cleanup facts.
6. Several mutation cases changed metadata or receipt admission rather than physical behavior, and the experiment manifest omitted the embedded Node fixture/physical study. 7. The original invoice server measured request length but did not consume the declared tenant/query/header semantics. The closed request DTO and physical policy matrix now make those bytes causal and include the tenantless seed-authority neighbor.
8. U4's new `internal/world` and adapter-model dependencies expanded the older U2/U3 mutation closures. Their positive manifests now review the exact transitive additions; composed U4 removes inherited duplicates and avoids nested source-scope overlap.
