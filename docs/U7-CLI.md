# U7 reference CLI and cross-domain evidence

Countershape's U7 reference application is a local Darwin instrument for two
checked-in studies. It executes trusted repository code with the current
user's permissions and host network access. Private temporary directories are
for repeatability and evidence separation, not security isolation.

## Commands

The ordinary human surface remains inert:

```text
countershape help
countershape validate --spec <path|-> [--json]
countershape preflight --spec <path|-> [--json]
```

The two study routes are machine-only and are admitted by the frozen harness:

```text
countershape study http --json
countershape study cli --json
```

An interactive request for either study is refused. The harness supplies an
exact clean fixture repository, one private scratch root, one empty private
evidence root, the admitted Git and Node executables, and ordinal `1`, `2`, or
`3`. A successful process prints exactly one four-field domain result after
the evidence tree has been terminally reopened.

## What U7D closes

U7D executes fresh same-ordinal HTTP and CLI workflows through the unchanged
sealed code surfaces without coercing one domain into the other. Its
reproduction package adds a fail-closed terminal-artifact check after each
package-owned handler succeeds: app first closes the retained Node runner,
captures the checked bytes, and reopens them unchanged while closing the
workspace before the collector may publish that run. An embedding may retain
one opaque collector across three HTTP and three CLI application invocations;
callers cannot construct or submit snapshots. That local closure establishes
only successful package-handler validation plus two matching terminal
artifact-byte projections. It establishes no harness process topology,
executable, stdout, environment, resource, receipt, or independently computed
semantic authority. The unchanged v2 harness—not one long-lived product
process—separately owns the actually executed six-process aggregate and
cross-run freshness observation. No parent run, artifact, event, claim, or
grade is reused.

The strongest truthful source-candidate verdict is:

```text
LOCAL_TWO_DOMAIN_PROCESS_ARTIFACT_GREEN_CLI_OFFICIAL_EXECUTION_HTTP_DIRECT_PROCESS_ONLY_FULL_STUDY_RESOURCE_UNRECEIPTED
```

This is deliberately mixed authority. The CLI side retains ten exact
target-bound finalized runs and matching classifications for the enrolled
normal-exit stimulus. The HTTP side retains fresh official targets and direct
standalone bundle-process observations, but no target-bound HTTP finalized-run
or classification authority. U7D does not manufacture those missing facts.

If the combined closure cannot be established, the ceiling is:

```text
ONE_DOMAIN_OFFICIAL_CONTRACT_EXECUTION_PLUS_HTTP_DIRECT_PROCESS_OBSERVATION_ONLY
```

## Harness evidence

The U7P-origin/U7N-amended v2 harness performs three fresh HTTP runs and three
fresh CLI runs. For each domain it directly observes the fixture repository,
prepare/compile/execute process topology, exact 111-file evidence tree,
deterministic-wrapper equality, fresh-wrapper nonaliasing, and direct subject
wall/RSS. Each run contains `1` fixture step, `1` compile step, `80` search
trials, `8` confirmation trials, and `10` contract trials.

The harness does not independently recompute product semantics or measure the
entire parent harness. The deterministic ruling, decision-record, and
contract-bundle files are labeled semantic regression projections; the fresh
typed authorities remain in the package-owned inspections.

## Explicit limits

The following remain unreceipted or absent:

- Linux, Windows, other Node majors, external platforms, and broad imported repositories;
- hostile containment, network denial, independent security review, and production readiness;
- comprehension, review compression, adoption, and maintainability;
- full-study resource bounds and imported-repository timing;
- HTTP finalized-run and classification authority;
- two-domain target/run/classification reproduction;
- generalized CLI official execution; and
- the U7D source receipt, which only U7R may reconcile.
