# Lane 6 — alternatives and adversarial interpretation

## Alternatives considered

| Design | Ruling |
| --- | --- |
| Three persisted objects | Retained after follow-up; highest audit clarity and preserves classification retry/versioning. |
| Target + run with nonpersisted view | Rejected after different-model review; loses immutable historical conclusion. |
| Classification embedded in run | Rejected; couples physical publication to predicate/classifier availability. |
| One post-run object | Rejected unless the pre-spawn durability claim is dropped. |
| Mutable semantic execution head/ledger/latest index | Rejected; duplicates Wake-like recovery semantics and violates nonhead scope. One private boot-session interlock is retained only as a spawn-safety blocker with no history/result authority. |

## Worst plausible superficially passing builds

- Treat a parsed target body or copied digests as runnable authority.
- Manufacture a one-candidate `WorldPlan` to reuse comparison execution.
- Execute current/dirty worktree bytes instead of the pinned materialization.
- Resolve Node through ambient PATH or reuse a stale probe.
- Parse generated TAP back into Go classification authority.
- Hash a declaration of absence rather than measure typed scope evidence.
- Publish an eligible run before teardown, drains, orphan probe, and scope closure.
- Treat every nonzero direct test as contradiction.
- Reissue a run permit after crash/lease expiry.
- Start a fresh target on the same boot while a prior spawn outcome remains unknown.
- Add a filesystem traversal or `latest.json` to recover nonhead objects.
- Weaken the old “C absent” checker without replacing it with exact C ownership.
- Infer platform/Node portability from schema acceptance.

## Scope ruling

P07B-C is too broad for one implementation prompt. Split semantic algebra, nonhead store, target authority, process/run, HTTP/standalone, and cumulative closure. Every predecessor must remain inert or capability-narrowed so an early unit cannot accidentally expose a weaker execution path.

## Kill/cut line

Stop at a receipted pre-spawn target milestone if any of these remain unresolved:

- direct single-target materialization would require forging comparison authority;
- admitted runtime cannot remain opaque through spawn;
- the winner-only start-intent primitive cannot prevent permit reissue;
- standalone evidence remains metadata-shaped rather than observer-produced;
- restart requirements require a mutable selector/head.

Do not downgrade those failures into a broader standalone claim.
