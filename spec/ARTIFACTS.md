# Countershape reduction artifacts

This note describes the U5 reduction wire split. The JSON schemas and examples are inert documentation of canonical semantic-body shapes. Passing schema validation never constructs a Go authority, proves a physical execution, establishes evidence freshness, or earns a reduction grade.

## Canonical bodies and typed digests

The four reduction bodies intentionally omit `artifact_digest`. Countershape computes each typed digest outside its own hash preimage from the exact canonical body bytes. A digest printed beside an object is an envelope or reference fact, not another semantic-body field.

| Canonical body | Owning package | What it records | What JSON possession does not establish |
| --- | --- | --- | --- |
| `ReductionRun` | `internal/reduce` | Original and minimized stimuli and measures, original divergent-baseline digests, reducer set, measure definition, scope, budgets, transcript reference, limitations, and the inward weak draft grade | A complete sweep, durable publication, or outward strong grade |
| `ReductionTranscript` | `internal/reduce` | Declared baseline map identities and sorted evidence links, ordered proposal evaluations, tri-valued decisions, terminal evaluator-protocol refusals, separate observed map digests, exact arithmetic over recorded trial counts, accepted proposal path, and final-sweep state | A trusted baseline authority, proof of physical work or elapsed time, typed `Evaluation` reconstruction, adapter stimulus bytes, a newly observed decision, physical freshness, or durable completion |
| `CompletedSweepDraft` | `internal/reduce` | One pure logical final-sweep set whose exact evaluations are all `CHANGES`, including the empty-set case | Durability, store-instance authority, or a grade transition |
| `ReductionGrade` | `internal/reduction` | The outward grade bound to the exact run and reducer set and, for the strong grade, the completed-sweep digest | Reconstruction of the opaque store capability or permission to manufacture the strong grade from serialized data |

The controlling implementation shapes are in [`internal/reduce/engine.go`](../internal/reduce/engine.go), [`internal/reduce/wire.go`](../internal/reduce/wire.go), [`internal/reduce/draft.go`](../internal/reduce/draft.go), and [`internal/reduction/finalize.go`](../internal/reduction/finalize.go).

## Outcome and preservation identities

`baseline_outcome_map_digest` and `baseline_preservation_map_digest` are deliberately separate fields:

- `OutcomeArtifactDigest` identifies one evidence-bearing outcome-map artifact, including its stimulus, phase, admissions, and evidence.
- `PreservationMapDigest` identifies the complete sorted eligible candidate-to-projection map only.
- Neither naked digest decides preservation. The typed comparability-first operation must first establish matching plan, envelope, comparison basis, roster, eligible set, and exclusions.

After an accepted preserving shrink, the run's original baseline outcome artifact and the completed draft's current minimized-baseline outcome artifact are expected to differ because their stimulus and evidence differ. Their preservation-map digests remain equal. The live `CompletedSweepDraft` generated by the run binds the current pair exactly.

## Grade separation

The pure reducer deliberately emits only `UNCHANGED` or `BEST_KNOWN` inside `ReductionRun`. It can also expose a `CompletedSweepDraft`, but that draft remains logical and copyable.

The outward transition is:

```text
live ReductionRun
  -> exact live compiled-WorldPlan-bound shrink budget
  -> exact live CompletedSweepDraft
  -> atomic store publication, sync, reopen, and parse
  -> opaque SweepCompletionAuthority for that store instance and draft
  -> internal/reduction validates authority first and binds the exact live run
  -> ReductionGrade
```

Only the last step may construct `ONE_MINIMAL_UNDER(reducer_set_digest)`, and only when the live budget retains the exact compiled `WorldPlan` digest matching the baseline plan and the logical sweep has no limitations. An ad-hoc `NewBudget` may drive a bounded weak run but strong finalization refuses it with `REDUCTION_BUDGET_PLAN_AUTHORITY_ABSENT`. A complete empty neighbor enumeration follows the same durable path. A zero, serialized/reconstructed, wrong-store, stale, mismatched, or post-corruption authority is refused. An ordinary in-process value assignment preserves the same opaque authority and is not a reconstruction. A missing authority follows the explicit weak path: an accepted reduction remains `BEST_KNOWN`; otherwise it remains `UNCHANGED`, with `DURABLE_SWEEP_AUTHORITY_ABSENT` disclosed in the outward grade limitations.

The strong grade is local to the exact reducer-set digest. That digest binds rule names and versions, the adapter-owned measure definition, and a policy scope containing fixed anchors, pins, execution shape, and enabled transform classes. The current reducible values are bound separately by the exact run stimulus and proposal identities. Typed evaluation evidence establishes content-addressed nonoverlap only, not physical execution or freshness. The grade is not a global-minimum or root-cause claim; both flags remain `false` in every reduction body that carries them.

## Replay and evaluator-refusal boundaries

A validated `TranscriptRecord` reconstructs the complete inert proposal intent for each recorded step: parent and neighbor identities, before/after measures, reducer name/version, locus, transform priority, purpose, and the historical decision. It commits to declared baseline outcome/preservation identities and four sorted baseline evidence domains, but those bytes are not self-authenticating baseline authority. `ExecuteReplay` additionally requires the matching opaque compare-owned `DivergentBaseline`, exact-matches both map identities and all four evidence lists, and requires the first archived parent to equal that baseline's stimulus before invoking a callback. It seeds its collision fence from the typed map. Transcript bytes alone can never execute replay.

For each recorded intent, the callback must return four structurally valid evidence-domain lists whose identities do not collide, within their respective domains, with the supplied baseline, archived evaluations, or earlier replay returns. A `ReplayReceipt` records that bounded noncollision result. It does not establish physical execution, freshness, correspondence to the proposal, reproduction of the historical decision, artifact authorship, an `Evaluation`, or a grade.

Once the evaluator callback is invoked, its proposal does not disappear merely because the callback violates the reducer protocol. An over-budget trial report, observed map with zero reported trials, a nonzero map-backed count that disagrees with the typed attempt-evidence cardinality, missing partial evidence, invalid result, or reused evidence becomes a terminal `UNRESOLVED` transcript entry. The terminal protocol reason codes are internal markers and are rejected from public `Evaluation` construction. Malformed map authority is dropped; structurally valid same-domain nonreused partial lineage is retained when admissible. Complete map-backed results must report the exact number of typed attempt identities. Counts attached only to unresolved or error evidence remain evaluator-reported trusted-edge accounting; transcript arithmetic cannot prove hidden physical work. If a callback reports more trials than its remaining configured allowance, the terminal entry records that reported count even though the cumulative count crosses the configured limit. The parser permits that single final breach only with the exact `EVALUATOR_EXCEEDED_CANDIDATE_TRIAL_BUDGET` reason and limitation, never in a complete sweep. Counts beyond the global canonical maximum refuse the whole run.

## Schema-validation boundary

The schemas reject unknown fields, missing required fields, malformed digest syntax, unsupported statuses, impossible fixed flags, and basic array or numeric-bound violations. The owning Go constructors and parsers additionally enforce relationships that this planning validator does not calculate, including:

- canonical byte equality and typed digest recomputation;
- measure digest reconstruction and strict decrease;
- transcript counter deltas and accepted-path derivation;
- exact parent/measure continuity, non-self neighbors, and reachable final-sweep control flow;
- typed run/transcript baseline-map linkage plus sorted baseline evidence declarations;
- the one terminal, explicitly disclosed evaluator-overrun exception to the configured trial limit;
- all-or-none unresolved evidence domains, reason-specific terminal accounting, and cross-entry evidence nonreuse;
- final-neighbor lexical order and exact final-sweep set equality;
- run, transcript, reducer-set, measure-definition, scope, budget, and limitation linkage;
- completed-draft evaluation-to-neighbor correspondence; and
- store durability, exact reopen, store-instance identity, and live-run binding.

The `.valid.json` files mirror the exact canonical field sets and show the intended cross-artifact roles. Their digest-shaped values are inert fixtures; schema validation does not recalculate the referenced semantic objects or upgrade those examples into runtime authorities.
